# Architecture Decisions

Append decisions; do not rewrite history.

| ID | Decision | Consequence |
|---|---|---|
| D-001 | Offline-first Flask + SQLite + Jinja + vanilla JS/CSS | No required cloud, Docker, Node, React, CDN, or frontend build step. |
| D-002 | Windows host with private-LAN access | Waitress listens on the configured port; do not expose the app publicly without a separate security decision. |
| D-003 | Thai-first, touch-first UI | Labels/workflows prioritize Thai cashiers and large, direct controls; receipt output supports 80 mm printing. |
| D-004 | Monetary values use integer satang | Convert only at input/output boundaries; never use binary float for stored money. |
| D-005 | Server owns business truth | Server revalidates money, stock, and permissions; browser totals are advisory. |
| D-006 | Sales and stock mutations are atomic and auditable | Use explicit transactions for multi-row writes and retain movement/audit history. |
| D-007 | Schema evolution is additive and data-preserving | Idempotent startup migrations support older databases. |
| D-008 | Roles are admin, manager, cashier with server-side permission checks | Menu visibility is UX only and must never replace route authorization. |
| D-009 | Release/UAT runtime data is isolated by `POS_RUNTIME_ROOT` | Release/UAT/tests use separate runtime roots. |
| D-010 | Original requirements remain authoritative | Compact AI documents provide navigation and current state but cannot silently narrow the accepted contract. |
| D-011 | Routine AI work uses scoped context packets | Read six compact files, then only affected files. |
| D-012 | Makro import tooling is development-only | Deployed POS stays Python-only; catalog barcodes and prices require owner approval. |
| D-013 | Online stock is reserved at submission and deducted only at delivery completion | Cancellation, rejection, and expiry release it; conversion, sale, payment, receipt, and audit commit once atomically. |
| D-014 | Customer identity uses a separate hashed-token session and non-enumerable public IDs | Customer routes never inherit staff authority; order access checks ownership. |
| D-015 | Expiry and notifications use access-triggered checks and local polling | No background/cloud dependency; relevant access expires orders and staff alerts poll every 15 seconds. |
| D-016 | Active, positively priced products are online-eligible by default; transfer destinations are reusable with one selected account | An additive migration enables existing products; managers can select an account without re-keying it. |
| D-017 | UAT customer ordering supports zero-price items, guest checkout, and payment at delivery | Superseded by D-024 for entry; historic UAT contact/PIN data remains preserved. |
| D-018 | Reconciliation prints a checked-order summary; fiscal sale and payment stay atomic at delivery | Early printing does not record payment; it states it is not proof of payment and D-013 remains the stock/financial boundary. |
| D-019 | Delivery staff reconfirm cash/transfer at handoff; automatic printing is limited to the Desktop Launcher profile | A changed method updates the order, payment, sale, and audit log. Other browsers offer explicit receipt/summary links. |
| D-020 | Receipt auto-printing uses a token-protected queue and off-screen kiosk browser; the Launcher otherwise prints normally | Narrows D-019 only: POS receipts and checked-order summaries auto-print; stock sheets and other documents use browser preview. |
| D-021 | Manager/Admin price changes save directly from product edit or filtered barcode lookup | Supersedes preview; changes remain server-validated in satang and create `change_price` audits. |
| D-022 | Staff order edits use current prices but retain the confirmed-price snapshot; assignment saves at delivery start | Edits atomically update reservation, totals, history, and audit; changed prices require reconfirmation. |
| D-023 | Runtime paths; Task Scheduler; Private/LocalSubnet firewall | Preserve legacy data. |
| D-024 | New online orders use verified LINE LIFF identity; guest and new phone/PIN checkout retire while history remains | Every new order has a verified LINE ID; staff access stays local unless approved. |
| D-025 | Negative stock is a configured operating mode applied consistently by server-side sale and online validation | When enabled sales may go below zero; transaction, stock-movement, and audit records preserve shortage visibility. |
| D-026 | Customer deletion is an audited anonymizing tombstone, not a relational delete | Preserve customer/order references and staff/time audit data; clear direct identifiers and unique constraints so the same person can register again. |
| D-027 | Product XLSX updates identify products only by immutable `product_uuid` | SKU, barcode, and names are mutable unique business fields and cannot be used for matching; blank UUID creates a new product and unknown/invalid UUID is rejected. |
| D-028 | Product XLSX previews are short-lived in process and stock is ledger-protected | Preview is non-persistent; confirmed new opening stock creates an audited atomic `opening_balance` movement. |
| D-029 | Public online ordering will use `online.raisanngam.com`; remote access to all POS features will use `admin.raisanngam.com` for Admins only | Customer traffic must be isolated to approved customer routes. The Admin hostname will require Cloudflare Access, an Admin-only application gate, and mandatory Admin 2FA; Manager and Cashier accounts remain LAN-only. This approves planning and Sprint 0 only—no public deployment is authorized until later security sprints and release gates are complete. |
| D-030 | Manager and Cashier staff access is localhost-only; remote staff access is limited to Admin through the configured Admin hostname | Supersedes the LAN-only staff wording in D-029. The application blocks non-loopback staff login/session use, and remote Admin requires Cloudflare Access plus application TOTP or a recovery code. Public host settings remain disabled until provider and release gates pass. |
| D-031 | Daily archives remain database-only with incremental VPS image sync; handoff and offline drills use a separate full recovery bundle | Keeps scheduled backups small while providing a verified database-and-product-image recovery point. The bundle must be copied off the POS disk; credentials and filesystem links remain excluded. |
| D-032 | Release 3.0.1 permits staff POS login and sessions from the configured shop private LAN `192.168.0.0/24`; the server uses static `192.168.0.200` | Supersedes D-030 only for direct private-LAN access. Requests outside the configured LAN remain blocked, the firewall remains Private/LocalSubnet-only, no router port forwarding is allowed, and public remote staff access remains Admin-only with Cloudflare Access plus application 2FA. |
| D-033 | The online catalog defaults to “สินค้าขายดี” ranked by all-time net sold quantity across POS and completed online sales | Net sold quantity is `sale_items.quantity - voided_quantity`; unsold products remain visible after sold products, category views use the same ranking, and a non-empty search ignores category scope so it remains global. |
| D-043 | Canonical local port-8000 Production was advanced to Release 3.0.7 on 2026-07-30 | Restart loads shared camera barcode scanning and the mobile quick-price numpad while retaining the runtime database, 449-product catalog, uploads, Cloudflare settings, and accepted `192.168.0.200/24` network contract. Site-LAN verification is deferred while the server is temporarily on another LAN; the startup task is absent. |
| D-044 | A missing price-control search may create an active product without an image | Manager/Admin must provide whole-baht price, Thai name, category, and unit. Creation is transactional, UUID-based, audited, duplicate-protected, and returns to a clean price scanner. Only successful active category/unit choices are remembered per staff; price, name, and quick-edit state are not shared. |
| D-045 | POS zero-price, unknown-barcode, and `MANUALPRICE` lines require an audit-backed manual price | Cashier entry is positive whole baht and does not change master price. Unknown barcodes create active offline-only zero-price placeholders only after confirmation. Each line stores and prints a one-use `MP-########` reference derived from its immutable price-entry audit; checkout revalidates staff/product/barcode/price, and scanning remains blocked until the prompt is resolved. |
| D-046 | Production server and cashier desktop run in separate Windows security contexts | `SaengngamPOS-Production` runs the port-8000 server as `SYSTEM` at boot. `SaengngamPOS-Desktop` runs an attach-only launcher for the passwordless standard local `POS` account at logon. A local token file connects its print-agent, POS has write access only to its browser profile and `runtime/pos-desktop/display_state.json`, and a Public Desktop shortcut reopens a closed launcher without restarting the server. Keeping mutable display state inside the writable parent ensures a server-created replacement inherits the correct ACL after reboot. |
| D-047 | The standard-user Desktop Launcher uses a private shared Python standard-library runtime | `desktop-python/` is copied from the installed server Python during elevated kiosk configuration, is read/execute-only to `POS`, and runs only `pos_desktop.py`. The launcher loads the standalone runtime-path helper without executing Flask package initialization. The server keeps its locked `.venv`; no permission is granted to an Admin user's private `AppData` Python installation. |
| D-048 | Manual POS selection uses independently configured text-only 3×3 menus rather than the product-category/image catalog | Manager/Admin owns audited menu and product positions. Positions paginate in groups of nine; search remains global, scanner/manual-price behavior is preserved, and POS does not request product images for these buttons. |
| D-049 | Canonical port-8000 Production was advanced to Release 3.1.0 on 2026-07-31 | Migration 28 adds empty POS-button mapping tables without rewriting the 735-product catalog or 0-sale history. The Release 3.0.9 SYSTEM server/standard POS launcher boundary remains; elevated task, backup, static LAN, firewall, runtime, health, and manager POS smoke checks passed. |
| D-050 | Release 3.1.1 reserves top-level POS menu position 9 for Manual Price and permits explicit cancellation of an unresolved manual-price prompt | This narrows D-045 only by treating an explicit cancel as resolution: no placeholder, cart line, manual-price reference, or audit is written, and scanner focus returns. While the dialog remains open, scanning stays blocked. The position reservation applies only to top-level menus; product slot 9 within a menu remains valid. |
| D-051 | A product may require an audit-backed price on every POS sale, and newly created products start offline | Migration 29 adds `products.requires_manual_price` default false. Flagged products keep their real UUID/name and master price but require a one-use Cashier-entered price per cart line. This extends D-045. The new offline default supersedes D-016 only for creation; existing online flags remain and Manager/Admin can explicitly enable a product later. |
| D-052 | Managers may maintain the main Settings page and settle billed balances | Migration 30 grants the existing `settings.manage` permission to Manager. This covers `/settings`, its reference and billing-customer controls, and individual/bulk billed-payment settlement with the acting staff retained in Audit. Cashier remains denied; staff, Audit, backup, maintenance, account security, and product XLSX remain Admin-only. |
| D-053 | Canonical port-8000 Production was advanced to cumulative Release 3.1.2 on 2026-07-31 | Migrations 29–30 preserve 742 active products and the zero-sale history while enabling per-product daily price entry and Manager Settings/billing access. Deployment also repairs the missing `SYSTEM` boot server and standard `POS` logon launcher tasks without changing the accepted Version 3.0.9 security boundary; verified backup, recovery bundle, rollback source, static LAN, firewall, runtime, integrity, and health gates passed. |
| D-054 | Existing-product XLSX import ignores `stock_quantity`; stock remains ledger-owned | Negative, stale, malformed, or edited stock cells for rows with an existing immutable `product_uuid` neither reject the row nor update stock. Admin catalog adjustments can proceed while receiving, stock adjustment, and stock count retain movement history. New-product audited opening stock remains supported. |
| D-055 | Release 3.1.4 is deployed only to an isolated port-8001 UAT source | Port 8000 Production is not restarted or modified. UAT reuses only `uat_runtime/`; candidate and Production assets have distinct verified hashes, and Production retains its pre-change asset until explicit deployment approval. |
| D-056 | Canonical port-8000 Production was advanced to Release 3.1.4 after explicit owner approval on 2026-08-02 | No migration or business-data rewrite was required. Verified database/recovery/source backups preceded promotion; the SYSTEM server and POS desktop tasks were repaired; Production and UAT finished healthy; raw asset hashes matched; Migration 30 and all measured business-row counts were preserved. Operational delays and corrective checklist items are retained in `docs/DEPLOYMENT_LESSONS.md`. |
| D-057 | VPS backup private keys used by the Production scheduler are owned by SYSTEM with explicit access limited to SYSTEM and Administrators | The in-process daily scheduler inherits the SYSTEM server context. Interactive Admin SFTP success is insufficient evidence because Windows OpenSSH evaluates private-key ownership for the caller. Production repair may correct local secret metadata without blocking offline POS startup; Production verification and the read-only SYSTEM connection tool expose any remaining local or transport failure. |
| D-058 | Canonical port-8000 Production was advanced to Release 3.1.5 after explicit owner approval on 2026-08-02 | No migration or business-data rewrite was required. Elevated lifecycle/runtime verification passed, and an explicitly approved full backup-and-sync under SYSTEM uploaded and download-verified the database archive plus 16 product images with zero errors. The Production stop lifecycle is port-scoped so isolated UAT below the install root is not stopped by a broad launcher match. |
| D-059 | POSPrinter POS-80 receipt output uses the driver's native `80(72)mm x 297mm` form | The driver models an 80 mm roll as a 72 mm printable canvas with hardware 4 mm side margins. Direct GDI receipts must select that form (and portrait orientation) rather than requesting an 80 mm printable canvas plus software side margins, which can clip the right edge. Top and bottom retain 4 mm software spacing; sales, inventory, and receipt content rules remain unchanged. |
| D-060 | The approved receipt logo is drawn within the SYSTEM GDI job | The printer-stored RAW-logo command is not reliable for the SYSTEM-owned Production service, despite working interactively. The same approved local `receipt-logo.png` is therefore read by the service and drawn at the top of the single GDI receipt job. This replaces the raw logo command to avoid duplicate logos; it keeps the single drawer pulse, receipt content rules, and business data unchanged. |
